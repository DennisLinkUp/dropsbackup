## Keywords (100 Zeichen)

App-Name + „Drops" werden automatisch indexiert — die Keywords sollten **andere Begriffe** sein die User suchen würden.

```
spontan,treffen,leute,kennenlernen,freunde,kaffee,bier,sport,realtime,nähe,bluetooth,karte,münchen
```
(99 Zeichen)

**Strategie:**
- Lokal: `münchen` (für regional ranking)
- Action-Verbs: `treffen,kennenlernen,spontan`
- Use-Cases: `kaffee,bier,sport,freunde`
- Tech-Hooks: `realtime,bluetooth,karte`

**Nicht aufnehmen:**
- „App", „Drops", „spontane Treffen" (Plural von included terms = wasted)
- „beste", „kostenlos", „neu" — wirkungslos in Apple-Search

## App Privacy (Datenschutz-Labels)

App Store Connect → App Privacy → Data Types

**Daten gesammelt:**

| Datentyp | Verwendung | Tracking? | Gelinked zu User? |
|---|---|---|---|
| **Vorname** | App-Funktion | Nein | Ja |
| **Geburtsdatum** | Altersverifikation, App-Funktion | Nein | Ja |
| **Email** *(Apple-Sign-In)* | Account-Erstellung | Nein | Ja |
| **Telefon** *(optional)* | Account-Recovery | Nein | Ja |
| **Standort (präzise)** | App-Funktion (Drops in Nähe) | Nein | Ja |
| **Avatar-Emoji** | App-Funktion | Nein | Ja |
| **Diagnose-Daten** *(Crashlytics)* | App-Funktion (Crashfix) | Nein | Nein (anonym) |

**Daten NICHT gesammelt:**
- Adressbuch / Kontakte
- Fotos / Mediathek
- Browsing-Verlauf
- Gesundheitsdaten
- Käufe / Finanzen
- IDFA / Werbe-IDs

## Review Notes (an Apple)

```
Drops ist eine soziale App für spontane In-Person-Begegnungen in deutschen Städten.

Test-Account: Nicht erforderlich. Apple-Sign-In wird genutzt — Reviewer kann sich mit jedem Apple-Account anmelden.

Funktionalität testen:
1. Apple-Sign-In durchführen
2. Onboarding: Name, Geburtsdatum (>= 18), Stadt-Auswahl (München für Test)
3. Standort + Bluetooth-Berechtigungen erteilen
4. Map-Tab: Drops in der Nähe sichtbar (sofern andere User aktiv)
5. „+"-Tab: eigenen Drop erstellen (Aktivität, Ort, Zeit wählen)

Hinweis zum BLE-Confirmation-Feature:
Der Reviewer kann technisch keine echte Drop-Begegnung simulieren ohne zweites Test-Gerät in räumlicher Nähe. Das BLE-Feature aktiviert sich automatisch wenn zwei Drops-User physisch beieinander sind (≤ 10m). Für Test-Zwecke kann der Reviewer:
- Einen eigenen Drop erstellen
- Den Drop selbst „bestätigen" über den Drop-Detail-Sheet
- Drop wird im Verlauf des Profils sichtbar

Datenschutz: Drops nutzt Firebase (Auth + Realtime Database). Daten werden in Frankfurt (eu-west-3) verarbeitet. Konto-Löschung über Profil → Einstellungen → Konto löschen, alle Daten innerhalb von 30 Tagen entfernt.

Bei Fragen: contact@drops-app.de
```

## Was nach Submission

**Typischer Apple-Review-Cycle: 1–3 Tage.**

Mögliche Rejection-Gründe (vorbereitet sein):
- **Guideline 4.0 Design:** Apple könnte stören wenn Walkthrough fehlt → mein Vorschlag „First-Drop-Walkthrough" wird relevant. Workaround für jetzt: Welcome-Sheet ist explanatorisch genug.
- **Guideline 5.1.1 Privacy:** wenn Privacy-Policy unvollständig
- **Guideline 1.2 Safety:** wenn soziale App nicht klar Reporting/Blocking hat — Drops hat Block-Funktion + Reliability-Score, sollte passen

**Bei Rejection:** in App Store Connect ist eine direkte Dialog-Funktion mit Apple. Antwort meist innerhalb 24h.

**Bei Approval:** App ist innerhalb von 24h live im Store. Bereite 2–3 Posts für IG vor (siehe `Instagram Posts/content_plan.md`) für Launch-Tag.
